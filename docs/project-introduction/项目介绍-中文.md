# 星契项目介绍

AsterLink · 角色化 AI 桌面启动器

把常用的 AI 应用化作可以召唤的伙伴，在一个桌面入口里完成选择、启动与切换。星契结合二次元角色大厅、召唤演出和常驻小窗，让日常使用多个 AI 工具的过程更直观，也更有陪伴感。

> 项目快照：2026 年 10 月 20 日 · 源码版本 0.3.6 · 当前面向 Windows。公开源码版使用星契 / AsterLink 品牌，附带 MiMo、Lumi 角色与小灵狐图标；旧内部安装标识及配置目录保留以兼容升级。历史 0.3.5 安装包包含未确认授权的素材，不属于公开发行内容。

![图 1 角色大厅。一个角色可以绑定多个 Agent，并以不同卡片展示。](../images/roster.png)

## 01 项目定位与用途

星契适合日常同时使用编程助手、通用对话工具和其他 AI 桌面应用的用户。它把分散的启动入口集中起来，让用户通过角色识别常用工具，查看进程状态，并在主界面收起后继续通过悬浮小窗访问已召唤的应用。

典型场景是：先为 Codex、Claude 等本机程序登记路径，再把它们分配给喜欢的角色；工作时从大厅召唤目标程序，之后通过小窗快速返回。角色与 Agent 是可配置的映射关系，角色名称本身并不代表模型接入。

当前产品承担的是本地应用启动与唤醒层。仓库中未见模型 API 调用、统一聊天界面、会话汇总或多 Agent 自动协作实现。CC Switch 按钮用于启动外部供应商切换工具，供应商管理由该工具承担。

## 02 已实现的核心体验

- 角色大厅：展示角色图片、角色台词与运行状态（公开版附带 MiMo、Lumi 角色，不内置第三方徽标）；单击查看详情，双击进入召唤流程。大厅按角色与 Agent 的组合生成卡片，并根据窗口尺寸适配布局。

- 连接配置：一个角色可以绑定多个 Agent，分别选择主页展示、召唤动画和台词池。首次使用时主页阵容为空，需要自行添加。

- 程序注册：设置页集中维护 Agent 名称与本机路径，支持扫描候选应用和手动浏览文件，避免在每个角色上重复配置路径。

- 桌面启动适配：区分普通 GUI 程序、控制台程序、快捷方式、协议链接和 WindowsApps 路径；实际兼容性仍取决于目标应用。

- 运行状态：主进程约每 5 秒读取一次 Windows 进程列表，变化时推送到界面。这里的“运行中”表示进程存在，不表示模型服务可用或窗口处于前台。

- 桌面驻留：托盘菜单支持快速召唤、主界面恢复和退出；已召唤小窗支持横排、竖排、固定位置与拖动。唤醒依赖目标应用对重复启动的处理。

- 常驻与偏好：可对选定应用进行最小化预热，支持开机自启、深浅主题、动画时长和关闭至托盘等设置。最小化行为受目标程序影响。

## 03 技术栈

| 层次 | 技术与实现 | 承担的职责 |
| --- | --- | --- |
| 桌面运行时 | Electron ^33.0.0 | 主窗口、透明小窗、托盘、系统对话框、单实例与开机自启 |
| 界面 | 原生 HTML、CSS、JavaScript | 角色大厅、配置表单、主题、动画和自适应布局；未使用 React 或 Vue |
| 系统能力 | Electron 内置 Node.js 与 CommonJS | fs、path、child_process；进程启动、文件配置及系统命令调用 |
| 进程通信 | contextBridge 与 IPC | 通过 preload 暴露有限接口；主窗口与小窗使用不同能力集合 |
| Windows 集成 | tasklist.exe、cmd.exe、Electron shell | 进程枚举、控制台启动、快捷方式解析、协议和商店应用打开 |
| 本地持久化 | userData/config.json | 保存角色、Agent 和偏好；配置版本升级前备份旧文件 |
| 构建分发 | npm、electron-builder ^26.15.3、NSIS | 配置 Windows x64 安装版与便携版；本轮未执行构建 |
| 视觉资源 | PNG 立绘、Agent 图标、多尺寸 ICO | 角色展示、应用标识、系统托盘及安装图标 |

以上依赖范围来自 app/package.json，不等同于本机实际安装版本。当前实现以本地文件与进程管理为主，不要求单独部署业务后端或数据库；目标 AI 应用自身的网络、账户和模型服务需求由各应用决定。

## 04 架构与数据流

```text
用户点击角色
  → renderer.js 读取角色与 Agent 映射并播放演出
  → preload.js 通过 IPC 发出启动请求
  → main.js 使用系统能力启动或再次打开目标程序
  → 记录已召唤项，更新托盘与 mini 小窗
  → tasklist 轮询状态并推送到界面

设置变更 → IPC → config-store.js → userData/config.json
```

app/main.js 管理窗口、系统集成、启动和进程状态；app/renderer.js 管理角色数据、交互和演出；两套 preload 脚本连接界面与主进程；config-store.js 负责配置读写和迁移备份。mini.html、mini.css 与 mini.js 构成独立小窗。

两个窗口均启用了 contextIsolation，并关闭 nodeIntegration。主界面不会直接获得完整 Node.js 能力，但 IPC 入参校验、内容安全策略和启动目标约束仍有进一步完善空间。

## 05 上手流程

- 在 app 目录安装依赖并执行 npm start。已有依赖时直接启动即可。浏览器打开 index.html 只能预览界面和演出。

- 在设置页登记目标程序，使用“选择”扫描候选项，或浏览本机文件指定路径。

- 进入连接配置，为角色勾选 Agent，并开启“添加到主页”。

- 返回角色大厅，单击查看详情，或双击召唤。召唤成功后主窗口退到后台，可使用小窗返回目标应用。

- 按需启用常驻预热、开机自启和小窗固定；常驻预热会启动被选中的第三方程序。

![图 4 已召唤小窗。左侧小灵狐返回主界面，其余图标访问已召唤的 Agent。](../images/mini.png)

## 06 未来优化方向

以下为根据当前代码提出的建议，其中品牌统一和发布资源分离已完成，其他建议尚未实现，也不代表已经承诺的发布计划。优先让启动可靠、等待可解释，再扩展个性化和自动化能力。

| 优先级 | 优化方向 | 具体改进与收益 |
| --- | --- | --- |
| P0 | 启动可靠性 | 统一去除路径首尾引号并验证目标；当前入口只做 trim。补充快捷方式参数解析、GUI / 控制台 / 商店应用兼容用例，让失败信息可定位。 |
| P0 | 配置与权限边界 | 配置写入改为临时文件加原子替换，校验数据结构并明确反馈失败；备份失败应可见。强化 IPC 校验、启动目标约束和 CSP。 |
| P1 | 启动等待体验 | 当前演出约在 4100 × animScale 毫秒后才提交启动请求。可提供“完整演出 / 快速召唤”，经确认后再评估演出与启动并行，分别衡量请求耗时和窗口可用耗时。 |
| P1 | 状态与唤醒准确度 | 从仅匹配 exe 文件名逐步增加路径、PID 或适配器信息；区分启动中、运行中和失败。为协议与商店应用建立专门检测策略。 |
| P1 | 品牌与工程整理 | 将新名称同步到界面、托盘、包元数据和文档；迁移时保留原 userData 配置。确认根目录 main.js 与 app/main.js 的维护关系，将截图脚本、历史图片与发布资源分离。 |
| P1 | 回归与运行诊断 | 围绕空阵容、多 Agent、配置迁移、引用路径、多显示器拖动和启动失败建立回归流程；增加可导出的本地诊断日志。 |
| P2 | 个性化与可达性 | 角色包导入导出、配置备份恢复、搜索与快捷键、减少动态效果、键盘焦点和小尺寸图标优化；后续新增角色素材须核实发布授权。 |
| P2 | 应用适配与平台扩展 | 建立目标应用适配层和统一启动能力描述，再评估 macOS / Linux。跨平台需要替换 tasklist、cmd、快捷方式及 Windows 登录集成。 |
| 探索 | 工作流能力 | 可研究工作区分组、一键打开工具组合和最近使用；若未来加入模型调用与 Agent 编排，应另行设计凭据、任务状态及权限模型。 |
